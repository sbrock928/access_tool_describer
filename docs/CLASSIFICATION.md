# Interpretation and Classification

V2 does not assign business purpose, roles, archetypes, narratives, migration sequences, or target
architecture with deterministic name heuristics. Static analysis produces only observed technical
facts: SQL operations and targets, connections, linked aliases, dependency edges, UI bindings,
VBA calls, files, coverage, and unresolved references.

The fixed local Qwen pipeline interprets each semantic-bearing unit once, or records an explicit
abstention/failure. Application synthesis uses every valid unit result plus the authoritative
graph and separately tagged owner claims. Every interpretation must close transitively to concrete
evidence. Pre-review model confidence is capped at medium.

Portfolio candidates are deterministic and overlapping: shared resolved endpoints, external
objects, files, exact normalized code, and semantic-profile similarity. Qwen can explain and
prioritize supplied candidates, but cannot change their membership or technical basis. Retirement
requires an owner lifecycle claim. Architecture and migration statements are cited proposals, not
observed facts.

Incomplete extraction suppresses unsupported absence claims. Missing, stale, or failed semantic
work is omitted only in an explicitly watermarked `report --allow-partial` run.
